# 编队后服务器错误弹窗恢复设计

**日期：** 2026-08-08

## 问题

经验本和纽本已成功进入编队界面并选中队伍后，`Battle.to_battle()` 会反复点击“开始战斗”。当游戏在该阶段显示“服务器发生错误。请稍后再试。”弹窗时，此循环未调用已有的服务器错误处理器，因此会继续点击被弹窗遮罩的开始按钮，造成无限卡住。

用户提供的 `C:\Users\g1582\Desktop\1786128864915.png` 已通过项目使用的 RapidOCR 识别出完整的错误文案、关闭按钮和重试按钮；现有 `find_server_error_dialog()` 可正确定位弹窗，且截图中的重试按钮可判定为金色可点击状态。

## 范围

仅修改 `Battle.to_battle()` 的截图与优先级处理流程：

1. 每轮获取彩色截图，以便现有恢复逻辑判断重试按钮的可用状态。
2. 在任何“开始战斗”模板识别或点击之前调用 `handle_server_error_dialog()`。
3. 已拦截且重试仍可用时，跳过本轮普通战斗点击；重试频率沿用处理器既有的五秒节流。
4. 重试已置灰而处理器关闭弹窗并重启游戏时，`to_battle()` 返回 `False`，使调用方停止本轮任务，避免对已重启的窗口继续操作。
5. 未发现服务器错误弹窗时，保持现有开始战斗逻辑不变。

不修改现有的经验本/纽本入口恢复、选队、启动页处理或弹窗的 OCR/HSV 判定规则。

## 实现方式

在 `tasks/battle/battle.py`：

- 导入 `handle_server_error_dialog`。
- 将 `to_battle()` 循环中的 `take_screenshot()` 换为 `take_screenshot_with_color()`。
- 截图成功后立即处理服务器错误结果：
  - `True`：继续下一轮，不执行普通识图或点击；
  - `False`：立即返回 `False`；
  - `None`：执行原有流程。

该设计复用 `tasks/base/retry.py` 中已测试的弹窗识别、重试节流、置灰关闭和重启行为，避免在战斗模块复制 OCR 或颜色判断。

## 回归测试

扩展 `tests/test_server_error_recovery.py`，为 `Battle.to_battle()` 添加独立测试替身：

1. 模拟彩色截图与处理器返回 `True`，并使下一次截图终止循环；断言没有调用“开始战斗”模板识别/点击。
2. 模拟处理器返回 `False`；断言 `Battle.to_battle()` 返回 `False`，且同样没有普通识图或点击。

测试应先在旧实现上失败：旧实现使用灰度截图，且从不调用处理器。最小实现完成后，针对性测试和全量 pytest 均须通过。

## 验收标准

- 服务器错误弹窗在编队后开始战斗阶段出现时，普通“开始战斗”点击不会与弹窗处理并行执行。
- 可点击的重试按钮由现有处理器按五秒节流处理。
- 置灰重试按钮触发既有关闭并重启逻辑，当前战斗启动流程返回失败。
- 不出现弹窗时，原有进入战斗流程行为不变。
- 新回归测试、既有服务器错误恢复测试和完整测试套件通过。

# 日常本批次导航设计

**日期：** 2026-08-08

## 问题

当前日常调度在批次入口已经执行一次 `back_init_menu()` 与 `make_enkephalin_module()`，但每一场经验本或纽本完成后，`onetime_EXP_process()` 和 `onetime_thread_process()` 又重复执行同样的两步。结果是经验本、纽本以及同一副本的多次执行之间都被强制送回主页、重复尝试换饼，再重新进入采光界面。

对本机 1.5.1 日志的核查表明该版本也有相同行为：经验本结束后立即记录“返回主界面”和“体力换饼”，再开始纽本。因此该改动是有意消除跨版本都存在的低效导航，而非恢复旧行为。

## 目标

一次日常任务批次仅在开始时回主界面并换饼一次；随后按当前调度顺序完成已配置的经验本和纽本次数，在副本之间直接复用采光导航。用户不应因切换副本或进行下一场同类副本而被频繁送回主界面。

## 范围

1. 保留 `Daily_task_wrapper()` 开头的 `back_init_menu()` 和 `make_enkephalin_module()`，作为批次唯一的常规初始化与换饼动作。
2. 移除 `onetime_EXP_process()` 与 `onetime_thread_process()` 成功战斗后的 `back_init_menu()` 和 `make_enkephalin_module()`。
3. 保留经验本、纽本入口函数已有的采光导航；它们从上一次战斗结算后的页面直接寻找对应入口，无法识别时仍可沿用现有主页导航分支。
4. 保留选队失败、开始战斗失败时返回 `False` 的安全中断语义；本次不将失败恢复策略扩展为自动回主界面后重试。
5. 不改变日常本执行顺序、次数计算、连续战斗拆分、后续领奖/镜牢调度或用户配置字段。

## 设计

`Daily_task_wrapper()` 是日常批次边界：进入批次时回主页并换饼，然后使用既有 `_single_combat_run()` 或 `_batch_combat()` 依序调用单场流程。

单场流程只承担“进入目标副本 → 选择队伍 → 开始战斗 → 等待结算”。成功结算后不再进行任何主页导航或换饼，从而让下一次调用直接通过 `EXP_luxcavation()` 或 `thread_luxcavation()` 的现有识图路径切换副本。

若选队或开始战斗返回失败，单场流程立即返回 `False`，调用链不会进入战斗操作。本次不增加新的自动恢复循环，避免把无关的恢复策略混入导航优化。

## 回归测试

新增日常批次调度测试，替换日常入口、战斗、主页导航与换饼依赖：

1. 经验本和纽本各一场时，断言批次仅调用一次主页导航和一次换饼，并依次执行两个日常流程。
2. 单场经验本和单场纽本成功时，断言都不会调用主页导航或换饼。
3. 保留已有测试：选队失败时，经验本/纽本流程不会调用 `battle.to_battle()`。

测试先在当前代码上失败，因为单场流程仍各自调用主页导航和换饼；实现后所有日常、队伍选择和服务器错误恢复测试均须通过。

## 验收标准

- 日常批次开始阶段只进行一次常规换饼。
- 同一批次内经验本、纽本及重复次数之间不再因成功结算而返回主页或换饼。
- 原有配置的副本顺序与次数保持不变。
- 选队或开始战斗失败时，不会继续执行战斗。
- 相关回归测试和完整 pytest 套件通过。

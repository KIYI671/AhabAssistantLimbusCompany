# 日常本批次导航设计

**日期：** 2026-08-08

## 问题

当前日常调度在批次入口已经执行一次 `back_init_menu()` 与 `make_enkephalin_module()`，但每一场经验本或纽本完成后，`onetime_EXP_process()` 和 `onetime_thread_process()` 又重复执行同样的两步。结果是经验本、纽本以及同一副本的多次执行之间都被强制送回主页、重复尝试换饼，再重新进入采光界面。

对本机 1.5.1 日志的核查表明该版本也有相同行为：经验本结束后立即记录“返回主界面”和“体力换饼”，再开始纽本。因此该改动是有意消除跨版本都存在的低效导航，而非恢复旧行为。

## 目标

每个已启用的日常项目在开始时初始化一次、在完成全部配置次数后回主界面并换饼一次：经验本整体和纽本整体各自独立。用户不应在同一项目的重复场次之间被送回主界面或重复换饼。

## 范围

1. `Daily_task_wrapper()` 不再预先执行批次级别的 `back_init_menu()` 与 `make_enkephalin_module()`。
2. `onetime_EXP_process()` 与 `onetime_thread_process()` 只承担“进入目标副本 → 选择队伍 → 开始战斗 → 等待结算”，成功后不进行主页导航或换饼。
3. 在经验本项目和纽本项目的全部配置次数完成后，各调用一次 `back_init_menu()` 与 `make_enkephalin_module()`。
4. 保留经验本、纽本入口函数已有的采光导航；同一项目的下一场从上一次结算页面直接寻找对应入口，无法识别时仍可沿用现有主页导航分支。
5. 保留选队失败、开始战斗失败时返回 `False` 的安全中断语义；本次不将失败恢复策略扩展为自动回主界面后重试。
6. 不改变经验本后纽本的执行顺序、次数计算、连续战斗拆分、后续领奖/镜牢调度或用户配置字段。

## 设计

日常调度将经验本和纽本视为两个项目组。一个项目组的全部单场或连续战斗批次完成后，调度器执行一次既有主页导航和换饼，然后才进入下一项目组。若该项目的次数为零，则不进行该项目的导航或换饼。

单场流程只承担“进入目标副本 → 选择队伍 → 开始战斗 → 等待结算”。成功结算后不再进行任何主页导航或换饼，因此同类副本的下一次调用可直接通过 `EXP_luxcavation()` 或 `thread_luxcavation()` 的现有识图路径进入下一场。

若选队或开始战斗返回失败，单场流程立即返回 `False`，调用链不会进入战斗操作。本次不增加新的自动恢复循环，避免把无关的恢复策略混入导航优化。

## 回归测试

新增日常项目组调度测试，替换日常入口、战斗、主页导航与换饼依赖：

1. 经验本和纽本各一场时，断言顺序为经验本 → 主页/换饼 → 纽本 → 主页/换饼。
2. 一个项目存在多次单场执行时，断言项目内各场之间不调用主页导航或换饼，且项目结束后只调用一次。
3. 单场经验本和单场纽本成功时，断言都不会调用主页导航或换饼。
4. 保留已有测试：选队失败时，经验本/纽本流程不会调用 `battle.to_battle()`。

测试先在当前代码上失败，因为单场流程仍各自调用主页导航和换饼；实现后所有日常、队伍选择和服务器错误恢复测试均须通过。

## 验收标准

- 经验本项目和纽本项目各在完成全部次数后只进行一次常规回主界面和换饼。
- 同一项目的重复场次之间不再因成功结算而返回主页或换饼。
- 原有经验本后纽本的执行顺序、次数和连续战斗拆分保持不变。
- 选队或开始战斗失败时，不会继续执行战斗。
- 相关回归测试和完整 pytest 套件通过。

# 服务器错误弹窗恢复设计

## 背景

Steam 版《边狱巴士》近期将“服务器发生错误。请稍后再试。”弹窗的按钮外观改为带完整边框的新样式。现有 `base/retry.png` 与 `base/retry_countdown.png` 是旧样式模板，无法在用户提供的错误截图中匹配。

当 `retry()` 未识别弹窗时会直接返回；纽本等任务继续执行常规界面识别，并反复点击底部“开始游戏”按钮，导致任务无限卡住。该问题已在 1600×900 和 1920×1080 的窗口设置下出现。

## 目标

在 Steam/Windows 模式下，检测此服务器错误弹窗后：

1. 阻止任务层继续执行普通界面点击。
2. 在“重试”按钮可用时，每 5 秒最多点击一次“重试”，且不设重试次数上限。
3. 识别到“重试”按钮变灰、不可用时，点击“关闭”，关闭并重启游戏，重新初始化后让既有任务流继续。
4. 不改变现有的倒计时重试、旧版重试弹窗、模拟器恢复和其他网络恢复行为。

## 范围与约束

- 仅修改当前项目，不修改 Steam、游戏程序、用户配置或存档。
- 不新增第三方依赖；复用已安装的 RapidOCR、Pillow、NumPy 与现有 `Automation` 接口。
- 不依赖固定的 2560×1440 坐标或用户截图制作新模板，以兼容 1600×900、1920×1080 和后续同布局缩放。
- 重试点击节流固定为 5 秒；首次识别到可用按钮即可点击。
- 关闭后仅重启一次并交回既有 `restart_game()` 流程；不在新恢复逻辑中自行递归或无限重启。

## 设计

### 弹窗状态识别

在 `tasks/base/retry.py` 增加一个独立的、可测试的服务器错误恢复辅助逻辑。

该逻辑使用当前帧的 OCR 结果一次性完成以下识别：

- 中文：同时存在“服务器发生错误”和“请稍后再试”；
- 本次范围限定为用户正在使用的简体中文游戏界面；英文界面继续保留既有旧版重试模板逻辑，不由本次改动扩展。
- 必须同时找到“重试”和“关闭”两个按钮文字，避免将其他普通“重试”或“关闭”误判为该弹窗。

OCR 坐标直接作为按钮中心候选坐标，因此不会使用绝对分辨率坐标。按钮词位于对话框下半部、且“重试”在“关闭”右侧，是额外的结构校验条件。

### 可用/置灰判定

将“重试”文字的 OCR 外接框扩展少量边距，在原始彩色截图中采样。可用按钮为金色文字，颜色通道差异和饱和度显著；置灰按钮的文字接近灰色，饱和度显著降低。

辅助函数只负责从像素区域计算“是否具有足够金色饱和度”，其阈值以单元测试中的金色与灰色样本锁定。像素范围为空或无效时保守判为不可用，避免在无法确认按钮可点击时继续误点。

### 恢复状态机

`retry()` 在获取新截图后、现有 `retry_countdown` / `retry` 旧模板分支之前调用服务器错误恢复逻辑：

1. 当前帧不是该服务器错误弹窗：返回“未处理”，沿用既有逻辑。
2. 是弹窗且“重试”可用：若距上次服务器错误重试不足 5 秒，保持在 `retry()` 中等待并刷新截图；否则点击 OCR 得到的“重试”坐标，记录时间，保持在恢复循环。
3. 是弹窗且“重试”置灰：点击 OCR 得到的“关闭”坐标，记录明确日志，调用已有 `kill_game()` 与 `restart_game()`，然后令 `retry()` 返回 `False`，由调用方停止当前旧任务循环。重新初始化流程将从任务调度层重新进入，避免在旧截图和旧任务状态上继续操作。

处理服务器弹窗时永远不会落入任务层，因此纽本、经验本、战斗以及 `back_init_menu()` 都不会继续点击各自的“开始”按钮。

### 可观测性

日志记录三种高价值状态：检测到服务器错误、节流等待/执行重试、检测到置灰并关闭重启。日志不记录截图像素或用户账号信息。

## 测试策略

新增纯 Python 单元测试，避免依赖 Windows 句柄、真实鼠标和 OCR 模型：

1. 用合成 OCR 条目验证：必须同时具备错误正文、左右按钮及其正确布局才认定为服务器错误弹窗。
2. 用合成 RGB 像素验证：金色文字区域判定为可用，低饱和灰色区域判定为置灰。
3. 替换 `auto`、时间函数和 `kill_game` / `restart_game` 为最小测试替身，验证：
   - 可用重试按钮首次点击一次；
   - 5 秒内不重复点击；
   - 5 秒后继续点击；
   - 置灰时只点击关闭并触发关闭、重启，且恢复函数明确返回中止当前调用方的结果。
4. 运行完整 `pytest` 与 `ruff check`；另以用户提供的截图离线运行识别验证，确认能提取中文错误文本、关闭与重试坐标。

## 验收标准

- 面对用户提供截图所示的服务器错误弹窗，系统能识别弹窗与两个按钮，而非使用失效的旧模板。
- “重试”可用时，最多每 5 秒点击一次，且弹窗存在期间不会执行纽本/经验本的普通开始按钮点击。
- “重试”变灰时，系统点击“关闭”并调用现有游戏关闭与重启流程。
- 单元测试、全量测试和 Ruff 检查全部通过。

# 日常本重试与结算恢复设计

**日期：** 2026-08-08

## 问题

本机实测日志与截图暴露了三条连续故障链：

1. 服务器错误弹窗首次出现时，游戏可能显示“重试4”“重试2”等倒数状态；当前逻辑只根据按钮文字区域的颜色判断，把倒数状态误作可点击重试并立即点击。若倒数期间呈灰色，当前逻辑还可能直接关闭弹窗、重启游戏，浪费等待后本可恢复的重试机会。
2. 纽本第二场战斗结束时，普通“战斗胜利 / 确认”结算页被镜牢 `battle_statistics_assets` 高相似度误判抢占；普通结算确认模板未命中，右下角“确认”未被点击。随后下一场纽本在结算页上寻找入口并超时。
3. 经验本或纽本入口函数超时后只 `break`，没有返回失败状态。调用方仍继续选队、开始战斗，导致在错误页面上盲操作。

## 范围

1. 服务器错误 OCR 中识别到“重试”后带数字时，视为游戏倒数状态：只等待，不点击、不关闭、不重启。
2. 重试按钮非金色时不再一帧即关闭；持续记录此状态，在明确等待上限后才沿用关闭并重启的恢复动作。
3. 普通日常战斗结算优先识别并点击普通结算“确认”；镜牢统计模板仅在镜牢战斗中参与该分支判断。
4. `EXP_luxcavation()` 与 `thread_luxcavation()` 成功进入编队时返回 `True`，入口重试耗尽时返回 `False`。
5. 经验本和纽本单场流程必须检查入口返回值；失败后立即返回 `False`，不调用选队或开始战斗。

不改变服务器弹窗的 OCR 文案定位、现有五秒点击节流、日常副本顺序、项目组换饼策略或镜牢战斗结算的既有处理。

## 设计

### 服务器错误状态机

新增轻量状态记录首次观察到“非可点击重试”的时间。若 OCR 的重试文本包含数字（例如“重试4”），立即判定为游戏冷却，记录日志并返回已拦截状态。若无数字但按钮非金色，则等待一个明确上限；上限内保持拦截而不关闭，上限超出后关闭并重启。按钮恢复金色时，清除等待状态，并按既有五秒节流点击。

### 日常结算优先级

`Battle.fight()` 对非镜牢战斗只以 `battle/battle_finish_confirm_assets.png` 进入结算分支并点击确认；不使用镜牢 `battle_statistics_assets` 作为普通日常的结算证据。镜牢战斗仍保留该模板分支。

### 日常入口契约

经验本和纽本入口函数从隐式 `None` 改为显式布尔结果。只有已进入编队时返回 `True`；循环耗尽时返回 `False`。上层单场流程收到 `False` 后写入错误日志并退出，不再进入选队和战斗流程。

## 回归测试

1. 服务器错误 OCR 包含“重试4”时，断言不点击、不开启重启，并返回拦截状态。
2. 非金色重试在等待上限前，断言不关闭；到达上限时才关闭并重启。
3. 普通战斗结算时，即使镜牢统计模板也匹配，断言优先点击普通结算确认。
4. 经验本和纽本入口循环耗尽时返回 `False`。
5. 单场经验本/纽本入口返回 `False` 时，断言不调用选队或 `battle.to_battle()`。

## 验收标准

- 游戏“重试N”倒计时不会被 AALC 点击或关闭。
- 普通纽本结算页的“确认”会在下一场入口寻找前被点击。
- 日常入口失败后不会再执行选队或开始战斗。
- 新增回归测试、已有服务器错误/日常/队伍测试与完整 pytest 套件通过。
- 实机连续纽本日志不再出现“结算页未确认 → 下一场入口超时”的序列。
